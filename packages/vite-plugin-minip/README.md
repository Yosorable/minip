# vite-plugin-minip

Develop a Vite frontend app inside [Minip](https://github.com/Yosorable/minip)
with native APIs and hot updates, then package and install it by QR code.

Requires Node.js 20.19+ or 22.12+ and Vite 6, 7, or 8.

## Usage

```sh
npm install minip-bridge@2
npm install -D vite-plugin-minip
```

Add the plugin alongside your framework's Vite plugin:

```ts
import { defineConfig } from 'vite'
import minip from 'vite-plugin-minip'

export default defineConfig({
  plugins: [minip()],
})
```

Keep your existing build command and add a packaging command to `package.json`:

```json
{
  "scripts": {
    "dev": "vite",
    "build": "vite build",
    "preview": "vite preview",
    "pack": "npm run build && npm run preview"
  }
}
```

`npm run dev` starts Vite and prints a development QR code. Connect your phone
and computer to the same network, then scan using a Minip app build that supports
development sessions. The app loads pages directly from Vite, keeps the native
bridge available, and receives Vite HMR or full-page reloads as you edit.
Keep the development server running. No ZIP or installation is needed.

`npm run build` creates `<outDir>/<app-name>.zip`. `npm run pack` also starts
the preview server and prints a QR code. Connect the phone and computer to the
same network, then scan using Minip. Keep the server running until installation
finishes. Rebuild and scan again to install an update.

Browser preview is available as usual. Native SDK APIs run inside Minip.

Development sessions use `appId` for native storage and permissions. These remain
available across hot updates and subsequent sessions, and are shared with an
installed app using the same ID. Memory storage lasts until the session closes.
Sessions do not add a project to the installed list or replace installed files.

Relative native routes and tab paths resolve against Vite's base URL. The local
HTTP server setting `webServerEnabled` does not apply to development sessions.
Rescan after changing native settings in `app.json`, such as tabs, orientation,
or navigation bars. JavaScript and CSS changes use Vite's normal update behavior.

If the page cannot load, Minip offers Retry and Close. Check that the server is
running and that Minip has local network access in iOS Settings. Vite handles
reconnecting its hot-update connection after a server restart. For HTTPS, the
phone must trust the development server's certificate.

## App metadata

Create `app.json` in the Vite project root, or let the first dev run or build create it:

```json
{
  "appId": "a-stable-unique-app-id",
  "name": "my-app",
  "homepage": "index.html",
  "version": "0.0.1"
}
```

Keep `appId` stable across updates. `name` determines the archive's filename.
Other Minip manifest fields, including tabs and navigation settings, are preserved.
The archive contains a generated `files` list so Minip can remove obsolete built
files during updates. This generated list is not written back to the source manifest.

Optional `icon` paths are relative to the app root. Put the file in Vite's
`public/` directory (for example, `public/icon.png` with `"icon": "icon.png"`)
or at that path in the project root. Icons are included in the generated file list.

## Configuration

```ts
minip({
  manifest: 'app.json', // Relative to Vite's root.
  qrCode: true,        // Print QR codes during development and preview.
})
```

The plugin uses Vite's resolved `root` and `build.outDir`. By default, it sets
`base: './'` for embedded deployment and exposes development and preview servers
on the local network. Explicit `base`, `server.host`, and `preview.host` settings
are respected. If a server listens only on localhost, no phone QR code can be
generated. Vite's existing HMR configuration is respected.

During development, the plugin serves the app configuration at
`<base>__minip__/app.json`. The development QR code contains a
`minip://dev/<encoded-server-base-URL>` link, or an array of links when multiple
network interfaces are available. The endpoint is not included in production
builds. The preview QR code continues to use `minip://install/`.

Use this plugin for frontend apps with an HTML entry. SSR and library builds
are outside its scope. Packaging requires files to be written to disk.

The archive is finalized in a sequential `closeBundle` hook with `order: 'post'`,
so files generated by other plugins, such as PWA service workers, are included.
If another plugin also uses a post-ordered `writeBundle` or `closeBundle` hook,
place `minip()` after it in the plugins list. Watch builds repackage after each
successful build and wait for finalization before rebuilding. The `[minip]
Packaged` message indicates that the ZIP is ready, including in watch mode.

For a new project with the SDK and plugin already configured, use
[`create-minip`](https://www.npmjs.com/package/create-minip).
